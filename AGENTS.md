# Personal site workflow

- Work directly on `master` and push to `origin/master`. The owner explicitly does not require pull requests for this repository.
- Deploy the frontend through connected Cloudflare Workers Builds and the inference service through GitHub Actions, both triggered by a push to `master`. Do not run local production application deployments or dashboard uploads. Server OS, runtime, and restricted SSH bootstrap are infrastructure setup; model/application releases still go through CI.
- Run `npm run check` and `node --test` before pushing code changes. Confirm the resulting CI build succeeds.
- Hosting must stay in the personal `michal@matloka.com` account pinned in `wrangler.jsonc`, never a work account.
- Reuse saved GitHub/Wrangler authentication and existing personal browser sessions. Do not repeatedly query 1Password from fresh shells. If a new credential is required, fetch only the specific task credentials once into a persistent process, then reuse them without further vault reads. See `infra/auth-session.md` for documented authorization limits; never promise a blanket 12h+ desktop authorization or claim a credential cache exists before creating it.
- Never commit credentials. Keep the site plain HTML, CSS, and JavaScript. The current goal adds a trained server-side generator; do not claim that a fixed catalog, image interpolation, or random image distortions fulfills it.
- The owner explicitly requires a no-prompt model like thispersondoesnotexist: the deployed generator receives fresh random noise and directly produces a priest portrait. A general-purpose text-to-image model with a hidden fixed prompt, cached text embeddings, or a randomly chosen prompt bank does not meet the requirement. Focus serving research on an unconditional priest-specific generator, such as an adapted pretrained face GAN. Diffusion may be used offline for teacher images or quality references, never as the proposed production request path. Do not resume a failed GAN experiment unchanged merely because it has the right interface.
- The user requires actual server image generation below 500ms and now accepts GPU hosting. Benchmark the final pipeline on the deployment hardware, including generation, quality checks/retries and encoding; distinguish warm runs, cold starts, queueing and public request latency. Local Mac timings or pre-generated queues do not prove this requirement. Compare pretrained bases before choosing post-training; GPU permission alone does not replace the prior preference for hosting below $15/month.
- Keep images, training datasets, and model weights in Git LFS. Store research code, provenance, logs, and evaluation artifacts under `research/`.
- Do not publish an unreviewed model as the production generator. The owner explicitly requires photorealistic visual quality comparable to thispersondoesnotexist. Verify facial integrity and detail at the displayed size, diversity across unseen latents, adult male priest appearance, white collars, and no hats. Distinct hashes, learned collars, passing infrastructure tests, or improving losses do not satisfy this quality requirement. Share checkpoint previews for non-blocking human review; the owner rejected the first pilot's step-1000 output as terrible.
- Third-party research code and weights retain their upstream licenses; the website/application code stays MIT.
- Use `git -c core.fsmonitor=false status --short` before archiving running research logs: the filesystem monitor has missed appended log/metric changes in this checkout. Stage complete checkpoint files only, never temporary writes.
- Before resuming the reference training run, use the separate provenance preflight in `research/experiments/reference_phases/resume-preflight.md`; retain a new output directory and explicitly review mismatches instead of regenerating the baseline to bypass them.
