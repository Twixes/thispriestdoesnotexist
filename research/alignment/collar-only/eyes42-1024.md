# Original-resolution eyes42 dataset

`eyes42-1024/` contains 110 unique 1024 × 1024 RGB PNGs, made directly from the same 110 original **1254 × 1254** portraits recorded in the accepted collar-only manifest. The PNGs total 91,884,165 bytes (approximately 87.6 MiB). No 256-pixel image was enlarged to create them. Existing source images, 256-pixel outputs, scripts, and manifests were not modified.

Run `research/alignment/.venv/bin/python research/alignment/prepare_1024.py` from the repository root to reproduce this dataset. Only the new 1024 outputs and their companion manifest/contact sheet are generated. Each input is hash-checked against the accepted manifest, and each existing eyes42 256 output is also checked before generation.

The script composes three homogeneous transforms:

```
M_original_to_1024 = R_256_to_1024 @ M_accepted_256_to_256 @ R_original_to_256
```

The resize coordinate mapping is `(pixel_center + 0.5) * target_size/source_size - 0.5`, matching the pixel-center geometry of the original PIL resize. It is not simply a multiplication of all translation terms by four. The composed matrix maps the full-resolution original directly to the final output in one `cv2.warpAffine` operation with `INTER_LANCZOS4` interpolation and the accepted `BORDER_REFLECT_101` border rule. No new face or collar detection, crop choice, or proportion adjustment is performed. The algebraic roundtrip back to reference coordinates differs by at most 5.69e-14 pixels on the checked points.

The accepted crop sometimes selects fewer than 1024 source pixels across its effective field of view, so some local interpolation enlargement is unavoidable. This retains the original-resolution detail instead of interpolating the already downsampled 256-pixel training image. The final image will not downsample bit-for-bit to the old PNG because the resampling sequence and kernel application differ; the framing geometry is preserved.

`eyes42-1024-manifest.json` records each source path, source hash/dimensions, accepted 256 image hash, both affine matrices, output path/hash/dimensions, pixel hash, byte count, and reflected-border fraction. It also records the parent manifest/review hashes, script hash, OpenCV/Pillow/NumPy versions, and coordinate conventions. All outputs were opened and checked for 1024 × 1024 RGB; all 110 hashes are distinct. Git attributes confirm these PNGs use LFS.

The complete contact sheet was inspected, followed by full-resolution `original-001`, `synthetic-140`, and the largest-reflection example `synthetic-122`. Faces and white collars retain their intended geometry, with bare heads. **The accepted reflection policy has a visible inherited defect:** `synthetic-122` mirrors strands of hair into the upper edge, creating a disconnected fragment. Its reflected area is 8.4%; `synthetic-102` and `synthetic-099` are the next highest-padding cases. This is more conspicuous at full resolution than in the earlier contact sheet. The requested transforms and border recipe were preserved rather than silently altering them. `eyes42-1024-review.json` records this limitation; the dataset has not received blanket high-resolution visual approval. Before final high-resolution training, decide whether to make a separately versioned border correction or exclude the affected inputs.

The new reference trainer can consume this directory using its disk/CPU microbatch staging. No training has been started with these files. The method should first be validated at 256 pixels; these prepared artifacts do not establish 1024-pixel model quality or production approval.
