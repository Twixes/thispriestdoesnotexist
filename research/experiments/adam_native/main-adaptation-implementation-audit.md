# Native AdAM main-adaptation implementation audit

2026-09-22. Prepared by reading pinned upstream source and current local interfaces. No model was loaded, no training or importance calculation was run, and no frozen implementation was changed for this audit. This document specifies a prospective runner; it does not report a successful priest model or a valid importance ranking.

## Current evidence and missing input

The completed `research/runs/adam-native1024-output-rank1-fixed-offsets100-v1/result.json` reports a successful 100-step stability run. Its continuation directory `adam-native1024-output-rank1-fixed-offsets100-to500-v1` contains restoration evidence and a metrics prefix through step 109 at inspection. A metrics prefix alone does not establish current process liveness or completion. Neither run is main adaptation. No directory matching `research/runs/*importance*` existed at inspection, and the inspected artifacts supply no empirical priest quantile decision.

The next main-adaptation experiment therefore still needs:

1. A completed, authenticated output-rank1 probing checkpoint, with its EMA G/D states, original-source/data pins and fixed-34-offset policy. Completion and image review must be rechecked when the current continuation finishes.
2. A fixed-policy-compatible importance evaluator. The existing `estimate_importance.py:pair_gradients` turns every parameter in its `named` input on, and its worker currently supplies every modulation parameter. Using it unchanged would enable the 34 coordinates deliberately excluded from this experiment. A separate implementation is being prepared; its tests and actual native result are not established by this audit.
3. Actual importance data: first a four-pair compatibility diagnostic, then the separately supervised 1000-pair estimate if the diagnostic's timing, state and gradient checks pass. Four pairs cannot establish trustworthy rankings. The accumulator must have complete G/D counts, all required names, finite nonnegative means, source checkpoint/protocol/sample-plan hashes and unchanged EMA states.
4. A declared quantile and fixed masks, plus a selection report. Published recipes use 50 for Babies and 75 for AFHQ-Cat; neither is a measured priest setting. No held-out/test images should enter training or FI.
5. The new fixed-offset adaptation helper, verified against actual updates and all alternating gradient toggles. The current `AdaptationMasks` intentionally implements the source-style policy, including trainable G noise and activation-bias offsets, and is insufficient alone for the current experiment.

## Source-backed schedule and first executable horizon

Pinned source is `upstream/source/AdAM_main_adaptation.py` at upstream revision `6428e99cfb36bc8bda3506350824f0c7dac9a5ad`. The launch file `_bash_main_adaptation.sh` requests 1500 iterations, batch 4, q50 for Babies; 2500, batch 4, q75 for AFHQ-Cat. It evaluates/stores samples every 100. The Python loop actually uses `range(args.iter + 10)`, so a native runner should explicitly execute its stated number of updates rather than copy that extra-ten behavior. Upstream main adaptation maintains G EMA only; retaining D EMA in our port would be an explicit optional diagnostic difference, not required serving state.

Keep the tested objective and constant learning schedule for the first main-adaptation trial:

| Setting | Value |
|---|---|
| Base learning rate | 0.002, no warmup/decay |
| G Adam | LR 0.0016; betas `(0.0, 0.99**(4/5))`; no weight decay |
| D Adam | LR `0.002*16/17`; betas `(0.0, 0.99**(16/17))`; no weight decay |
| D objective | `softplus(-D(real)) + softplus(D(fake))`, mean |
| G objective | `softplus(-D(G(z)))`, mean |
| R1 | gamma 10, every 16 loop indices including 0; coefficient 80 |
| Path regularizer | weight 2, every 4 including 0; coefficient 8, target decay 0.01 |
| Style mixing / augmentation | probability 0.9; real horizontal flip only |
| G EMA | fixed decay `0.5**(32/10000)` |
| Initial resource configuration | native 1024, CPU FP32, one thread, batch 1, unfused modulated convolution |

**First native horizon: exactly 10 main-adaptation iterations**, with previews at 0 and 10, one terminal full checkpoint, and an immutable resource/parameter report. That exercises 13 G optimizer updates and 11 D updates including second-order regularizers. This is justified by the existing ten-iteration compatibility protocol, and is newly necessary because main adaptation adds original-weight gradients and Adam moments absent during probing. Reuse the current 35% start / 20% runtime available-memory floors, 12 GiB process-tree RSS and 512 MiB swap-growth limits, with a declared bounded wall deadline (1200 seconds is a conservative proposed smoke limit, not a measured runtime). Do not run alongside the heavy probe/FI worker.

If the smoke passes, extend that exact main-adaptation state to a **100-iteration visual checkpoint**, then schedule a source-referenced **1500-iteration development run** only after image quality and memory are reviewed. A 100-step preview does not demonstrate convergence. At batch 1, 1500 iterations expose the model to fewer real images than the published batch-4 recipe; it is an initial development horizon, not claimed sample-count equivalence. Do not automatically increase to 6000 or change LR to compensate. Step counts are `G=N+ceil(N/4)` and `D=N+ceil(N/16)` for a fresh run; N100 gives 125/107, N1500 gives 1875/1594.

**Quantile recommendation, conditional on valid FI:** predeclare q50 as the first development-only arm because it is an actual published recipe, then compare q75 with identical fresh-source seeds, data, schedule and preview latents if q50's development results justify a second arm. This is an experimental choice, not priest-specific calibration or evidence that q50 is optimal. q75 protects roughly the highest 25%, not 75%, and allows more original rows to fine-tune. Report all layer/pool counts and ties. An all-zero/all-equal FI pool should trigger investigation before training instead of silently treating its all-low masks as an informed decision. A 1000-example estimate alone does not establish stable masks; use saved prefixes and disjoint sums to report rank and selected-set stability.

## Minimal runner and exact interfaces

Create a new versioned runner; do not modify or repurpose the live continuation, earlier probing, modulation, selection or mask sources.

1. **Authenticate and normalize FI once.** Read the selected completed importance marker and file using `weights_only=True`, verify actual bytes and source lineage, reconstruct each `EmpiricalSquaredGradients.from_state_dict(state['G'/'D'])`, and call `mean_squared_gradients()`. Do not pass `gradient_sums`, already-normalized means masquerading as sums, or a raw folded generator as a proxy for the parameterized EMA checkpoint. Bind the decision to actual pair count. Produce `selection-G.json` and `selection-D.json` via `select_rows(named_means, inventory, quantile=q)`, with hashes and a separate human-readable decision record.
2. **Reset to original source, not probing.** Construct native G and D from the authenticated metadata, load original G_ema export and original D export strictly, use fresh independent RNG state for factor initialization, and install `output_rank1` modulation. Do not load probe G, D, EMA, Adam, path mean or RNG states. Probing enters this stage only through FI-derived selection. This also resets the probe-trained D epilogue. Keep original source G/D hashes in the main protocol.
3. **Install fixed-policy masks before creating Adam.** Call the separately tested fixed-offset controller using the G selection; use the appropriate D controller with D selection. Their public contract must retain `named_parameters()`, `parameters()`, `set_enabled(bool)`, `bind_optimizer(opt)`, `step(opt)` and `verify_invariants(opt)`, or the runner must explicitly adapt to a different documented interface. Construct two fresh plain Adam instances from controller parameters and bind them while their state is empty. Do not use `set_probing_grad`, `set_stability_grad`, `probing_parameters` or whole-model `requires_grad_(True)` afterward. The fixed policy must exclude all 34 offsets from gradients and optimizer groups for every phase.
4. **Verify the real initialization.** Save original G output and D logits on fixed fixtures before masking; verify fresh modulation and low-row zeroing preserve them exactly in FP32. Capture the same four unfiltered development latents used by the probe for comparisons. Create G EMA as a copy of the fully initialized, masked G, rather than separately initialized factors. Any retained D EMA should similarly begin as a copy. EMA updates should change values only, never enable gradients or introduce optimizer state. Save explicit trainable/protected names, counts, shapes, ordering and policy metadata.
5. **Run a fresh global loop from index zero.** During D phases disable G through its controller and enable D through its controller; fake generation for D can be no-grad. During G phases disable D parameters through its controller while retaining D's image Jacobian. Preserve the tested non-saturating/R1/path formulas, mapping `skip_w_avg_update=True`, stochastic training noise, real sampling and flip behavior. Replace every direct optimizer update with `controller.step(optimizer)` after its corresponding backward, including R1 and path. Clear stale `.grad` values explicitly when alternating if fixed-offset invariants require absence, not merely `requires_grad=False`. Path target begins at scalar zero and is included in subsequent exact resumes.
6. **Check the right invariants.** Protected original rows, low-score factor/bias entries and their Adam moments must stay exact. Legitimate low-score original rows must be allowed to move; the probing helper's whole-frozen-source assertion would reject correct adaptation. Original G synthesis activation biases/noise strengths and their 34 offsets stay fixed under the new policy. G mapping/ToRGB/first4x4 originals stay frozen while their allowed adapters train; D fromRGB originals stay frozen, D epilogue trains fully. Verify the G EMA fixed offsets separately. Keep all source buffers fixed, including mapping w_avg and constant-noise buffers.
7. **Write a resumable checkpoint plus independent export.** Atomically save raw G/D, G EMA (and D EMA only if deliberately retained), both Adam states, global RNG, data-sampling RNG, path target, actual update counts, preview-latent identity, selections, fixed policy, ordered optimizer names, protocol/runtime/source hashes and controller policy metadata. Checkpoint controller installation/rebinding must be designed explicitly: current `bind_optimizer()` rejects existing state and implicit replacement, and constructor zeroes low entries/captures references. A valid resume should install the same masks on authenticated original models and bind empty Adam, then restore checkpoint model/optimizer state and verify protected slices/moments against original references. Do not construct a fresh controller on already-adapted weights and thereby bless corrupted protected values. Prove resumed next-update equality before a long extension.
8. **Fold and compare without changing the working model.** Use `fold_modulation(G, inplace=False)` and separately fold G EMA if exported. Compare native outputs on all fixed latents with identical noise/flags. Keep model/image/checkpoint artifacts in Git LFS with original licenses. Do not equate exact fold with fast serving; latency remains a later measurement on the actual server.

## Pitfalls confirmed in existing implementations

- `AdaptationMasks` selects 16 G convolutions and 16 corresponding affines at 1024, plus 24 D residual convolution/skip modules. Affine masks are independent of their convolution masks. Mapping, first 4x4, ToRGB, fromRGB and D epilogue have explicit separate policies. Do not copy upstream's hardcoded 256-resolution layer indices or 5-D weight slices.
- `selection.select_rows` expects complete architecture metadata, output-rank1 layout and already-normalized CPU floating tensors. It computes three separately pooled linear-interpolation percentiles with strict `>` membership; ties are low. Bias-bearing D and G affine scores divide the three-term sum by **two**, as in executable source. G convolution scores do not use synthesis activation-bias or noise-offset FI, so excluding the fixed 34 names from a new FI input need not invent zeros for selector-required coordinates.
- Existing `AdaptationMasks` snapshots protected slices and verifies all parameters and Adam states after updates; it does not clamp or repair failures. Its validation allows `grad is None` for some trainable tensors. The runner should retain family-level finite/nonzero-gradient checks and actual optimizer counts, rather than assuming the controller alone proves all intended families trained.
- Low-row original gradients and moments allocate full tensor storage in ordinary Adam even if most rows are protected. Thus q75 versus q50 is not a proportional memory reduction; any selected tensor with low rows may allocate full gradients and two full moment tensors. The old 9.93 GiB probing peak cannot establish compliance for main adaptation under the 12 GiB guard.
- Current mask construction records metadata on the model and rejects a second controller. Deep-copying a controlled model preserves that metadata; do not then attempt to install another controller on the EMA copy. EMA should have no controller or optimizer needs, only value/policy validation.
- Upstream main adaptation freezes original G activation bias/noise but trains their offsets. The fixed-34 policy is an intentional evidence-driven departure from AdAM and must remain named in the protocol; it is not a faithful upstream reproduction. The corrected convolution layout, native1024, G_ema reset prior, batch1/CPU and source-scaling preservation remain other disclosed differences.
- The native dataset is only 20 synthetic training portraits. Source coherence, finite losses, stable FI, or priest collars do not establish adult male coverage, attractiveness, no hats, independent identities, lack of copying, or photographic realism. Do not rate apparent minors for attractiveness. Development preview review must inspect every fixed sample rather than filter failures.

## Existing test evidence and next implementation tests

`test_adaptation_masks.py` already specifies seven tiny-network tests covering actual native32 adversarial/R1/path Adam steps, output-row support, independent affine masks, low-original movement, exact protected slices/moments, folding, inventory rejection, all-high/all-low policies, optimizer restrictions and selector integration. These tests were read for this audit, not rerun, and they exercise the old trainable-offset policy. They do not validate a future runner's checkpoint lifecycle, native memory usage or quality.

The new runner should have a bounded tiny-network integration test using its real training/update/checkpoint helpers: exercise all four update types with nontrivial mixed masks and the fixed-offset controller, confirm fresh-source reset rather than probing values, perturb/restore and compare the next update exactly to uninterrupted training, preserve preview RNG, and fail on changed masks or checkpoint lineage before mutating the active state. A deliberately stale Adam moment in a protected row must be detected. After that test, the supervised native10 smoke above is the first evidence for actual whole-run mechanics and memory; only subsequent reviewed development outputs can justify spending the longer adaptation horizon.

The final user requirement remains a genuinely random, prompt-free, high-quality adult male priest generator on the real server with measured generation below 500 ms. None of these prepared interfaces or proposed horizons proves that outcome.
