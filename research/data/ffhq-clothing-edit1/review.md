# Clothing-edit calibration: promising geometry-preserving example

This single built-in imagegen edit is a positive test of the proposed data method. The result is photographic, depicts the same apparent adult man with a bare head, and adds a convincing black clerical shirt with a visible white collar tab. Face placement remains close to the FFHQ reference without an alignment warp or reflected padding. It is not output from our trained priest generator, is not production-approved, and has not been added to any active training dataset.

## Measurements and grayscale control

Both original files were converted to RGB and resized to 256-square with Pillow Lanczos before the same YuNet detector ran. Coordinates below are normalized to image dimensions. The source is 1024-square; the raw built-in edit is 1254-square and remains unchanged.

| Image | Mean eye Y | Interocular distance | Mean mouth Y |
| --- | ---: | ---: | ---: |
| Original RGB source | .46299 | .22751 | .73935 |
| Original source, grayscale control | .46573 | .24618 | .73127 |
| Built-in clothing edit | .46732 | .24719 | .73006 |
| Previously measured FFHQ reference mean | .46593 | .25216 | .72932 |

The direct RGB-source versus monochrome-edit comparison fails the prospectively proposed limits: maximum five-landmark Euclidean displacement is .04340 against .015, and interocular distance changes +8.65% against 5%. These unadjusted results are retained in `geometry.json` rather than discarded.

However, a control converting only the original source to grayscale in memory produces a .04100 maximum detected landmark shift and +8.21% interocular change, with no geometric operation at all. This demonstrates that color treatment substantially confounds this detector on this particular image. It would be incorrect to attribute all of the raw measurement difference to edited facial geometry.

Comparing the grayscale source with the monochrome edit gives:

- Maximum landmark displacement **.00565**, or 0.565% of image width, below the .015 limit. This is approximately 1.45 pixels at the 256px detection size.
- Mean landmark displacement **.00341**, approximately 0.87 detection pixels.
- Interocular scale change **+0.407%**, below the 5% limit.
- Eye and mouth mean positions differ by only +.00159 and −.00121 respectively.

Both prospective preservation checks pass with matched color treatment. These are detector-level checks, not a claim of identical facial pixels, biometric identity, or proven training effectiveness. The grayscale control is not a new image artifact or a modification of the original: it exists only in the measurement process.

## Visual review

The source and edit were explicitly viewed at native size, and `comparison.png` was reviewed with both shown at exactly 256px. Facial structure, expression, gaze, hair, pose, and background appear closely preserved. Skin detail remains photographic; the edit does not exhibit the ghosted or duplicated features seen in the rejected trained checkpoints. The black-and-white treatment preserves useful tonal detail.

The clothing change is clear at both sizes. The white tab lies immediately below the chin and very close to the bottom edge; it remains visibly identifiable as a clerical collar. No hat, repeated hair, reflected shoulder, or added border is visible. There is no enlarged head-and-shoulders composition: the face stays at FFHQ-like scale and position.

The observed native quality supports a second small controlled edit test using a different source. It does not establish a success rate across sources, diversity of a future dataset, or improved convergence of a trained generator. Preserve paired source/edit provenance and measure each new example before deciding whether to assemble a dataset. No active-data addition is authorized by this review.

## Reproduction and provenance

```sh
research/alignment/.venv/bin/python research/data/ffhq-clothing-edit1/measure.py
```

The script runs on CPU with two OpenCV threads and no neural generator inference. It verifies the source checksum from `prompt.json`, records both file hashes and dimensions, five normalized landmarks, exact comparison values, detector/script/prompt hashes, and library versions in `geometry.json`. It writes only diagnostic metadata and `comparison.png`; it never writes either source image.

The original source is `research/runs/inference-cpu/ffhq1024/docker-4g/sample-002.webp`, SHA256 `9469812e8ae0be5a83274184bdc896235a3fb1df25361d4d494d12822a079216`, generated by the unadapted NVIDIA FFHQ1024 G_ema. Its seed and model provenance are preserved in `prompt.json` and the source benchmark artifacts. The edit is `001.png`, SHA256 `751a47d9e0d5c9a87c0e6f2d1a6447f2d24a90f4e862a562486cd554f85c5aec`.

No crop, affine warp, padding, reflected content, GPU work, training update, or production configuration change was performed. One attractive edited example is evidence about preparing data, not evidence that a deployable priest generator now exists.
