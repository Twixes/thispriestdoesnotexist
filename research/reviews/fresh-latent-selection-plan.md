## Minimal candidate pipeline

1. Draw a fresh `secrets.token_bytes(32)` seed for every attempt; retain the exact service PCG64 float32 latent convention, pinned generator, psi and constant noise. Run the generator. No approved-seed lookup or neighborhood sampling.
2. Reject mechanical failures: failed/nonfinite inference, wrong dimensions, failed face detection/restoration, missing provenance, or deadline. Require a single confidently detected main face, but treat this only as a detector check: it can miss partial people and architecture. Preserve raw output for diagnostic review.
3. Apply the frozen GFPGAN recipe, monochrome conversion and exact serving encoder. Evaluate the **decoded final image** with frozen CLIP full-frame features. Use separate adult/male-appearance and headwear comparisons as provisional research gates; add a supervised artifact probe trained on native judgments of head/face integrity, extra people, and background mergers. Keep a separate collar-validity label. Do not claim a generic “photorealistic priest” text similarity detects these specific failures.
4. Only candidates passing every mandatory gate can reach an independent calendar-appeal gate. Attractiveness is the owner's subjective preference, not an objective property or proxy for adulthood. Never score youthful/age-uncertain images for attractiveness. An unvalidated taste head means the “only hot” pipeline is unfinished.
5. Return the first passing freshly generated image. Initially cap at three serial full attempts plus a measured wall deadline; exhaustion is an uncached503, never relaxed thresholds, a stored image, or a stored accepted seed. The cap/deadline must be confirmed against actual combined runtime before serving. Research logs may preserve every seed for reproducibility but must not become runtime sampling input.

Dimensions, hashes, finite tensors and elapsed time are objective checks. Age appearance, masculine presentation, headwear/collar detection and artifact detection are fallible visual judgments/model estimates. Calendar appeal is a separate subjective judgment. `uncertain` always abstains from acceptance; it is not silently converted to reliable negative training truth.

## Concrete offline pilot after restoration review

Use the existing32 restored reference625 outputs as development data, keeping the complete denominator. Two native reviewers independently label each raw/final pair before viewing model scores: adult appearance, masculine presentation, bare head, single subject, recognizable plausible clerical collar, coherent anatomy/head boundaries, photographic detail, and—only for clearly adult masculine cases—calendar appeal. Resolve disagreement conservatively as uncertain. A narrow Roman tab is useful, but a complete collar inside the crop is not a user requirement; a plausible visible white clerical collar is.

Freeze CLIP and extract one512-D full-frame embedding per final decoded image. Fit **one** L2 logistic artifact-acceptability probe first, using the existing SciPy optimization pattern, train-only standardization, fixed lambda1, no hyperparameter search or encoder fine-tuning. Exclude uncertain labels from fitting, retain them in acceptance audits. If native review supplies fewer than eight clear positives or eight negatives, do not pretend this probe is estimable: collect another predeclared32 development attempts instead. A 512-D probe trained on32 examples is a feasibility test with high overfit risk. Existing zero-shot signals are comparison baselines, not the answer. Other mandatory heads/taste ranking need their own sufficient labels; do not merge all failures into “unattractive.”

Then draw **32 new calibration attempts**, all disjoint from all existing train/evaluation seeds. Freeze a small threshold grid in the experiment manifest before encoding; use calibration only to select conservative thresholds with zero observed mandatory false accepts. If every threshold fails or accepts nothing, report failure. Freeze all model/preprocessing/threshold hashes before drawing **64 further untouched test attempts**. Do not stop after enough good images, replace failures, alter prompts, or tune against test mistakes. Run in resource-guarded batches sized from the actual restoration measurement; no assumed runtime allowance increase.

Report on the same64 tests: accept-all, existing CLIP-only baseline, and CLIP+artifact-probe. Native-review every accepted and rejected image with scores hidden. Retain per-attempt seed, z/model/restorer/selector/encoder hashes, stage timings, labels, scores, rejection reasons, error status and all raw/final image hashes. Show attempts → successful generation → restoration → mandatory acceptance → appeal acceptance, both conditional counts and fractions of **all64 attempts**. Include uncertain/failed attempts, label-specific false accepts, eligible false rejections, duplicate/near-duplicate observations and chronological three-attempt request exhaustion. This is not a selected-gallery review.

Stop this candidate if it accepts any apparent child/uncertain-age image, hat, major anatomy/architecture merger or malformed priest clothing in the held-out set. Poor taste agreement is a separate failed appeal gate. Zero accepts, very low yield, or resource/deadline failure is also a failed practical pilot; do not improve coverage by weakening mandatory gates. Zero failures in a small accepted subset still does not justify production or an adult-only guarantee. A successful pilot warrants larger fresh accepted-output validation, including at least300 independently reviewed acceptances and a combined Linux serving memory/latency test. No validation images become a bank of accepted seeds.
