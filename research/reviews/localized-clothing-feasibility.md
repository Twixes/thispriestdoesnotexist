# Localized learned clothing editor: feasibility and one bounded test

2026-09-21. Assessment only: no weights downloaded, models loaded, compute experiments started, core code changed, or deployment performed.

**A frozen 1024px face GAN plus a small learned clothing editor is a credible inexpensive hypothesis, but not an established solution.** Its useful difference from our failed paired experiments is that it learns pixels in an explicit garment region and copies the source face, instead of asking shared StyleGAN synthesis weights to change clothing without changing faces. It retains a true random-latent GAN as the source of every new identity. The trained component is a conditional image editor; describe the resulting system as a composite GAN pipeline, not a successfully fine-tuned priest StyleGAN.

## What the existing evidence rules out

The four completed paired factorial arms all failed photographic collar quality after 300 additional updates. None reached convincing collars on four of six supervised identities; pitted necks, pale skin-like bands, and poor unseen generalization persisted. See [authoritative final decision](factorial-ABCD300-audit/root-final-decision.json). Another small change to the same losses or block range is not the next experiment.

The existing `paired7/manifest-proposed-v2.json` has six training identities and one held-out identity; `paired10/manifest-proposed.json` adds three diagnostic identities with reviewed masks. Native teacher edits are 1254px and are resized into the exact 1024px source coordinate system. These are not perfectly aligned full-image pairs: some edited faces or necks move. Existing masks intentionally exclude changed source facial pixels. Several intended tabs conflict with immutable source anatomy: b2-042 retains only 37.35% of its annotated target tab; old 000 and b2-020 retain approximately half. Such examples cannot demonstrate full-tab reconstruction under hard preservation. The masks themselves are manual annotations, not a ready inference-time predictor.

Our FFHQ1024 baseline already produced a 1.503 GiB cgroup peak and 4.48-second warm median in a one-CPU Linux container **under Apple Silicon amd64 emulation**. This is useful memory evidence but not native VPS latency. See [actual benchmark](../runs/inference-cpu/ffhq1024/docker-4g/README.md). The generator remains frozen and need not run during editor training because source images are already saved.

## Architecture proposed for the pilot

Let S be a newly generated source, E the editor, M an allowed garment/lower-neck mask, and P a separately defined protected face/hair mask. Restrict M to exclude P. At inference construct Y = S outside M, with the learned garment prediction inside M; feather only inward within M. Use exact source pixel copying after rendering to guarantee no editor changes outside M in the uncompressed image. JPEG/WebP encoding can change those pixels, so measure the invariant before lossy encoding. This invariant preserves source defects as well as good features: it does not certify anatomy, adulthood, attractiveness, or bareheadedness.

Use a modest image-space U-Net, trained from scratch, with source grayscale plus mask and coordinate channels. A four-level 16/32/64/128-channel network with skip connections and a one-channel output is a concrete starting design; require under two million parameters. Predict the full fixed lower-image crop at its native pixel scale, then hard-compose through M. Begin with rows 512–1023 of the 1024px image, **only after confirming every selected mask lies entirely there**; otherwise enlarge the crop and record it. Do not silently clip target garments or resize tiny tabs to near-zero support. Grayscale matches the site and reduces output complexity. No face reconstruction loss is needed: face pixels are copied.

This is inspired by paired image translation, not a faithful pix2pix reproduction. [The original pix2pix project](https://phillipi.github.io/pix2pix/) establishes learned conditional image translation as a general method, including photographic synthesis; it does not establish few-pair priest clothing quality. Its adversarial formulation could later improve fabric detail. First diagnose supervised fitting without a new discriminator, since a discriminator trained on six garments would introduce another overfitting problem. No need to download a new large model for this test.

## One bounded next experiment

1. **Teacher-composite feasibility first.** Reconstruct all six training and four available held-out/diagnostic pairs using original source pixels outside the existing masks and edited pixels inside. Inspect the native neckline/skin joins. Record every result. If these oracle composites already fail at the boundaries, stop: training cannot repair an impossible target while preserving the same mask. Identify at least four feasible training pairs before proceeding; predeclare exact IDs, masks and hashes. Keep the remaining pairs visible as failures rather than fixing their masks after viewing model results.
2. **Two-hour maximum, local only.** Initialize the small U-Net once with a recorded seed. Train batch 1, balanced identity schedule, Adam at 1e-3, at most 1,000 updates. Fix half of normalized L1 weight on the feasible tab and half on the remainder of allowed clothing; add a fixed 0.1 normalized image-gradient L1 inside the allowed mask to preserve boundaries. These are engineering choices, not validated optima. Save at 0/100/300/1,000, plus exact configuration/optimizer/RNG state. No parameter sweep. Use ten real updates as a timing and backward smoke; stop at 8 GiB sampled RSS, insufficient free memory, nonfinite state, or the two-hour wall limit. Use no overlapping heavy training process.
3. **Test reconstruction before buying data.** Show all training outputs, oracle teacher composites, and the four existing held-out/diagnostic identities at 1024. Success requires multiple bounded white tabs, plausible black fabric, no unnatural skin-to-fabric join, and exact protected-pixel preservation. A drop in L1 or perfect face-copying alone is not success. The held-out masks are oracle inputs, so results establish clothing rendering conditional on a supplied mask, not full inference capability. If it still cannot fit four feasible training collars, stop this editor recipe; do not automatically add examples or steps.
4. **Only after that gate, expand to 64 newly paired identities.** Predeclare 48 train / 8 validation / 8 test identities, keeping all original diagnostics out of final evaluation. Use diverse adult men, beards, neck lengths, yaw and visible clothing; request teacher edits that preserve pose and source boundaries. Generate synthetic teachers only for clothing, retain originals, prompts, masks, rejected edits, exact latent tensors and provenance in LFS. Do not call 64 enough for generalization before measuring it. A subsequent 128–256-pair expansion should depend on unseen improvement, not be assumed necessary upfront.

The 64-pair stage also needs an **automatic mask strategy** evaluated on entirely fresh samples. Candidate: use existing facexlib parsing/landmark weights to protect face/hair/ears and locate the lower neck, then train a small source-to-allowed-mask head from reviewed masks. Our installed restoration helper currently uses parsing to blend aligned faces, which is not evidence it supplies reliable shirt/neck masks in original 1024 coordinates. Test that separately. A learned alpha without an independently validated protected region does not guarantee face preservation. Conservative mask failures may reject a source, but record rejection cost and coverage; never substitute a bank of approved seeds. Manual masks at serving would fail the goal.

## Data and resource economics

Training changes a small editor instead of rebuilding the face prior. With at most two million float32 parameters, weights plus gradients plus two Adam moments total at most approximately 32 MB decimal; activations and framework overhead dominate. One 16-channel feature at 1024×512 costs 32 MiB. This makes an 8 GiB pilot ceiling plausible, not a measured result. CPU training time and serving latency are unmeasured. Benchmark the actual editor and mask predictor rather than inferring speed from file size.

No new teacher outputs are needed for the first fitting test. For the later stage, using the earlier conversation's **quoted**, not independently revalidated, 1024px high-quality output estimate of $0.05268/image: 64 output attempts cost $3.37; 256 cost $13.49. At 70% usable yield, obtaining 64/256 usable targets requires approximately 92/366 attempts, costing $4.85/$19.28 in outputs. Prompt, reference-image inputs and actual retries are extra. These figures illustrate data scale only; verify actual current model availability/prices before spending. A 70,000-image synthetic dataset is unnecessary for this adaptation hypothesis, and these small budgets are not proof that hundreds of pairs suffice.

CPU hosting remains plausible only if the complete fresh-source → eligibility → mask → garment → encode pipeline fits measured memory and acceptable latency. If a fraction q of FFHQ samples passes eligibility, source generation alone costs about 1/q attempts per delivered portrait; retain q in every benchmark. Do not import the failed restored-256 selector's acceptance rate as FFHQ1024 evidence. Load shared models once, serve sequentially initially, and benchmark 32 genuinely new eligible outputs plus all rejects in a Linux memory/CPU cap. No rented training compute or hosting purchase is justified by this memo alone.

## Fidelity to the requested goal

A successfully trained editor operating on a new GAN latent for every request provides genuinely new generated identities, retains GAN-based generation, and uses locally trained weights. It is not a fixed gallery or interpolation system. It is also **not the same architecture as one adapted StyleGAN network producing the whole priest image**. The user should see that distinction; do not label completion as “trained priest StyleGAN” if only the conditional editor was trained. Quality, attractiveness, bareheaded adult-male eligibility, fresh identity diversity, automatic masks, serving cost, and production deployment remain independent unproven requirements.

The cheap next action is therefore the source/teacher composite gate, followed by a single small-editor fitting test only if the composites are plausible. This is narrower and more informative than another long whole-face GAN run, but it must remain an experiment rather than a promised low-cost solution.
